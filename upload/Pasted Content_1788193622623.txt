# MASTER PROJECT PROMPT — ONLINE ESSAY WRITING COMPETITION MANAGEMENT SYSTEM

## 1. PROJECT OVERVIEW

Build a complete, production-ready **Online Essay Writing Competition Management System**.

The system will be used to organize essay-writing competitions for school students.

The application must support:

* Student registration
* Teacher registration
* Teacher-assisted student registration
* Student profile management
* Age-based competition eligibility
* School information
* Registration fee collection
* Razorpay payment integration
* Email verification
* Competition notifications
* Essay PDF upload
* Secure file validation
* Cloudinary file storage
* Examiner management
* Multiple examiners evaluating the same essay
* Examiner marks, comments and justification
* OCR-assisted quotation/reference from essays
* Automatic average/final score calculation
* Administrative financial management
* Complete audit logging
* Admin dashboard
* Competition configuration
* Notification management
* Production deployment on Vercel
* Neon PostgreSQL database
* Resend email service
* Cloudinary file storage

The system must be designed as a **real production application**, not as a demo, prototype, or toy project.

---

# 2. REQUIRED TECHNOLOGY STACK

Use a modern, maintainable stack compatible with Vercel.

Preferred stack:

* Next.js with App Router
* TypeScript
* React
* Tailwind CSS
* shadcn/ui or equivalent professional component system
* PostgreSQL
* Neon PostgreSQL
* Prisma ORM or Drizzle ORM
* Resend for transactional emails
* Razorpay for payments
* Cloudinary for essay/file storage
* Server-side API routes / Server Actions where appropriate
* Secure authentication with role-based authorization

Use environment variables for all secrets.

Never hard-code:

* Razorpay keys
* Database credentials

* Cloudinary credentials
* Authentication secrets
* Encryption keys
* Other sensitive configuration

# 9. REGISTRATION FLOW

### Teacher registration

Teacher:

1. Opens registration page.
2. Enters required information.
3. Creates account.
4. Receives verification email through Resend.
5. Verifies email.
6. Logs in.
7. Accesses Teacher Dashboard.
8. Adds students.

### Student direct registration

Student:

1. Opens registration.
2. Provides details.
3. Verifies email.
4. Completes profile.
5. Selects/apply for eligible competition.
6. Pays registration fee.
7. Payment verified by server.
8. Registration becomes confirmed.
9. Thank You / Confirmation page displayed.
10. Confirmation email sent.

### Teacher-assisted registration

Teacher:

1. Logs into dashboard.
2. Adds student.
3. Student record is created.
4. Student receives invitation/verification email.
5. Student verifies email.
6. Student sets/activates login credentials.
7. Student completes profile.
8. Student pays registration fee.
9. Registration is confirmed.

Never automatically mark a registration as paid merely because the Razorpay checkout page was opened.

5 MB

* MIME type

* File size
* PDF readability
* Corruption
* Malformed file
* Potentially dangerous embedded content
* Filename
* Metadata where relevant

# 16. FILE SECURITY

Because uploaded documents are user-generated content, implement a strong upload security policy.

Consider:

* MIME validation
* Magic-byte validation
* PDF parser validation
* Sanitization
* Safe filenames
* Random storage identifiers
* No executable content
* No direct execution
* Access-controlled delivery
* Signed/private Cloudinary URLs where appropriate
* Rate limiting
* Upload quotas
* Authentication requirement

Do not expose internal storage paths.

Do not trust:

* Client filename
* Client MIME type
* Client file size
* Client metadata

Server must independently validate everything.

# 20. MULTIPLE EXAMINER EVALUATION

Multiple examiners can evaluate the same essay.

Example:

Essay X:

* Examiner A → 82
* Examiner B → 88
* Examiner C → 85

Final average:

85

The system must automatically calculate the average according to the configured scoring policy.

Do not simply overwrite previous examiner marks.

Every examiner evaluation must remain independently stored.

Store:

* Examiner ID
* Essay ID
* Score
* Justification
* Comments
* OCR references
* Evaluation timestamp
* Submission/finalization status
* Version if edited/reopened

Admin should be able to configure:

* Number of examiners
* Maximum marks
* Minimum marks
* Averaging method
* Whether outlier handling is required
* Tie-breaking policy if needed

# 22. OCR SUPPORT

Where technically appropriate, provide OCR-assisted extraction.

The examiner should be able to select/reference text from the essay for remarks.

Example:

Examiner selects a section of the essay.

System extracts/copies text.

Examiner can attach that text to:

* Justification
* Comment
* Evaluation criterion

Do not automatically trust OCR as authoritative.

Clearly distinguish:

* Original PDF content
* OCR-generated text
* Examiner-written comments

If OCR cannot reliably process a PDF, the examiner should still be able to manually enter remarks.
